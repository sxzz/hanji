# 已知问题

## 「只有日本不同」偏多

**现象。** 早期版本里，四地常用字中约五分之一被判为「只有日本写法不同」，其中很多字（了、人、子、水、金……）用肉眼看四地根本没区别。当时的判定只用 Source Han Sans，结果是几乎找不到「四地完全一致」的字。

**排查。** 先怀疑是重复字形导致的假阳性 —— 两个不同的 CID 画出同一个形状。用 fontkit 取出真实轮廓逐字比对，结论是**不成立**：CID 判定与轮廓判定逐字吻合，那些差异在数据上是真实存在的。

也试过用「不重合面积占字面比例」做连续度量，来给一个可调的容差。度量本身可用（了 10‰、學 17‰、分 28‰、人 30‰，而骨 59‰、返 87‰、直 198‰），但「疑似噪声」与「真实差异」两组的分布重叠得厉害（中位数 60‰ vs 76‰），单靠阈值切不干净。这条路已放弃，代码未保留。

**现在的做法。** 改用 Source Han **Serif** 作独立的第二证据：只要黑体或宋体之中有任意一方认为两地同形，就算同形。依据是 —— 如果某个差异是地区规范的差异，两套字体都该体现；只有一套体现的，是那套字体的设计取舍。

实测两套字体在 8,475 行中判定一致的有 7,619 行（89.9%）。其中 201 行是「黑体说只有日本不同、宋体说四地全同」，了、人、子、水、金、色都在里面；合并后：

|              | 仅黑体判定 | 黑体∪宋体 |
| ------------ | ---------- | --------- |
| 四地完全一致 | 1,441      | **1,719** |
| 只有日本不同 | 1,335      | **1,178** |
| 四地各不相同 | 642        | **593**   |

**仍未解决的部分。**

1. 剩下的 1,178 行「只有日本不同」里，两套字体口径一致，但不排除 Adobe 在两套字体里沿用了同一套地区映射决策 —— 即证据并不完全独立。要证伪需要引入 Source Han 之外的第四方字体，或直接比对各地规范文件本身。
2. 合并的代价：被判为同形的格子会改用同组代表地区的字体渲染，因此 Noto Sans JP 自己那个略有出入的字形不会显示。这是「视为一样」的应有之义，但确实丢失了信息。若日后要做「字体差异」而非「地区差异」的视图，需要另一套渲染路径。
3. 判定的对象终究是 Source Han 的地区字形设计，不是各地标准。可考虑引入 GlyphWiki 的 `uXXXX-{g,t,h,j}` 地区变体作第三方交叉验证。

## 笔画数按地区取，日本那一列常与其他三地不同

笔画数逐地区取，优先级是 `kAlternateTotalStrokes` → `kRSAdobe_Japan1_6`（仅日本）→ `kTotalStrokes`。前两个字段目前只有日本一列用得上。

改动了 799 行，分两类，性质不一样：

- **日本自己画一个字形**（636 行）。少写或多写一笔：突 8（穴＋大，不是犬）、海 9（毎，不是每）、器 15、類 18。这一列以前沿用 `kTotalStrokes` 的 zh-Hant 值，对这些字是错的。
- **字形与他地相同，只是数法不同**（163 行，其中 45 行四地字形完全一致）。日本把 阝 数作三画、ネ 数作五画：那 6 / 6 / 6 / 7，都 10 / 10 / 10 / 11，阿 7 / 7 / 7 / 8。这些行四格里的字一模一样，笔画那行却分成两段——看着像 bug，其实是检字传统的差异。

**残余风险。** `kRSAdobe_Japan1_6` 在 Unihan 里的状态是 Provisional，而且偏旁的数法并不自洽：那 的 阝 按日本算三画，祁 的 ネ 却按中国算四画。拿 Unihan 专为此设的 `kAlternateTotalStrokes` 作尺子——两者都有值的 102 个码点里吻合 95 个（93%），不合的七个全是这类偏旁。`kAlternateTotalStrokes` 更准，但只覆盖 104 个码点，所以只能放在第一优先级兜底，不能当主源。另有 853 行不在 Adobe-Japan1-6 里（噹、彆、夠 这类日本标准不收的字），退回 `kTotalStrokes`。

## 什么算一个字组

**一行就是一个字。** 比如 國 那一行：大陆写 国，香港、台湾写 國，日本写 国，四列摆的就是这四种写法；行的名字（也是网址）用传承字形 國。

难就难在一句话上：**两个形到底是「一个字的两种写法」，还是「两个不同的字」？**

这件事本项目不自己判断，只用两份现成的公开数据，让它们互相纠正：

- **OpenCC 的对照表**，管简繁、港台异体、日本新旧字体的换算；
- **各地的规范字表**（大陆《通用规范汉字表》、台湾《常用國字標準字體表》、香港《常用字字形表》、日本《常用漢字表》），管「这个地方到底收哪些字」。

下面四条规则就是这么来的。

### 一、字表分开收的，不合并

OpenCC 的表里混着两种关系：

- **同一个字的不同写法**，比如 裏 / 裡 —— 照着换算是对的；
- **拿一个字去代替另一个字**：台湾用 著 兼表「著名」和「看着」，战后日本用 欠 代 缺、缶 代 罐、弁 代 辨/辯/瓣。

第二种照搬就出事：被代替掉的那个字（著、欠、缶、弁）本身就是现行汉字，一合并它就没有自己的行了。

**规则：某地的字表把两个字分开收录，就说明那个地方认为它们是两个字，不合并。** 大陆、香港、日本的字表都同时收了 著 和 着，所以 著 保住了自己的行。这样一共救回 19 个字：么 机 并 复 苏 著 坏 秘 予 宁 夹 欠 霉 虱 弁 咤 缶 苎 糸。

**这里有个坑**：字表里带括注。香港写 `別﹝别﹞`、`溫〔温〕`，日本写 `剝﹝剥﹞` —— 括号里的是同一个字的另一种写法，不是第二个词条。所以判断前得先把括注剔掉（`parsePrimaryCharList`），否则 别、温、説 这些纯字形差异会被当成两个字，凭空多出四十来行。

### 二、字表自己说是一个字的，合并

反过来的毛病：一个字被拆成了两行。

日本的换算表里有 `群 → 群 羣`、`唇 → 唇 脣`、`峰 → 峰 峯` 这样的条目，**箭头右边把字本身也写进去了**，意思就是「这两个形是一个字」。于是两个形都成了行名，一个字占两行 —— 一行带着香港的写法，一行带着其余各地的。

**规则：箭头右边包含字本身，就合并。**

这条判断不会误伤，因为另外两种关系长得不一样：代替只写另一个字（`台 → 臺`、`欠 → 缺`），不包含自己；一简对多繁来自另一张表（`复 → 復 複 覆`、`苏 → 蘇 甦 囌`）。所以 台/臺、复/復/複/覆、后/後 仍各自成行。另外，两个形算出来四列完全一样时（才 与 纔）也合并。目前一共 48 组。

### 三、规范字表说了算

OpenCC 和规范字表冲突时，以规范字表为准。

台湾《常用國字標準字體表》收的是 脣、祕、羣、峯、牀，香港《常用字字形表》也以这些为主字，可 OpenCC 一律换算成 唇、秘、群、峰、床。本站是照着规范字表建的，所以那两列写规范表的形。

### 四、先定四列，再定行名

合并完要挑一个形当行名。直觉是「哪个形出现在最多列里就用哪个」，但这样会选错。

`戸` 是日本的简化形，OpenCC 里没有它的任何换算，所以它那一行四列全是 戸戸戸戸 —— 看着像「四地都这么写」，其实只是没数据；而 `戶` 那一行知道自己在大陆是 户，四列是 户户戶戸。照「出现最多」选，日本的简化形就当上了行名。

**规则：先按第三条把四列的字定下来，再从中挑出现次数最多的当行名**（并列时看几个地方的字表收它，再比码点）。戶 因此保住了地址，塡 让位给 填、呉 让位给 吳。

### 一个字同属两组时，两边互相提示

日本用 欠 写 缺，而 欠 自己也有一行。两边的详情页在「另见」里互相链接：缺 的页面写「日本用字「欠」另有条目」，欠 的页面写「也是「缺」的日本用字」。弁 的页面同时指向 辨、辯、瓣 三组。

### 还没解决的

1. **43 处**：我们显示的形，在那个地方的字表里是括注在别的主字底下的（香港 `面﹝麵﹞`、`岡〔崗〕`、`櫃〔柜〕`）。这些多半是两个不同的字被放在一起作注，照搬主字会把 麵 并进 面，所以没动。
2. **130 处**：那个地方的**所有**字表都没收这个字，我们退回显示传承字形。几乎全在日本那一列（檯、噹、迴、錶、註、儘 都不是常用漢字），香港有 闇、孃 两个。收录等级已经是 0，这应该是对的表现。
3. 只有一个地方收录、别处没有对照的字仍可能被误合并 —— 第一条规则要两个地方对照才生效。
4. 台湾《次常用國字表》6,331 字不参与建行，其中约 3,589 个字完全不在表里。这是收录范围的取舍，跟合并无关。
