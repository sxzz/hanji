# 数据规则与已知限制

这份文档说明当前数据如何决定一行、五地展示形和不确定关系，以及哪些边界是有意保留的。已经解决的排查过程不再作为“已知问题”保留；实现和回归样例以 [数据生成器](../scripts/build-data.ts) 与 [数据测试](../scripts/tests/chars.test.ts) 为准。

## 收录范围

一行表示一个字组，五列依次是中国大陆、香港、台湾、日本和韩国的展示形。行由以下五份主表的并集生成：

- 大陆《通用规范汉字表》；
- 香港《常用字字形表》；
- 台湾《常用國字標準字體表》；
- 日本《常用漢字表》；
- 韩国《漢文教育用基礎漢字》（2000 年版，1,800 字）。

台湾《次常用國字表》和日本教育汉字表只补充已有行的收录等级与候选，不生成新行。台湾次常用表中只在该表出现的条目因此属于产品范围外，而不是遗漏。韩国列默认关闭，但数据、筛选和详情页均完整保留，可在显示选项中启用。

## 什么算一个字组

字组关系来自 OpenCC，地区字表用来约束它。项目不使用 Unihan 自动裁决，也不维护人工例外表；证据不足时宁可拆开。

- **分开收录就分组。** OpenCC 同时记录同字异形和一字代用另一字。若某地字表把两边都作为主条目收录，就保留两个字组，例如 `着/著`、`欠/缺` 和 `缶/罐`。
- **明确同字才合并。** OpenCC 自包含的同字关系，或两个名称算出完全相同的五列时可以合并，例如 `群/羣`、`唇/脣`；至少有两个地区佐证的映射可以作为确定的地区对应使用，但不会吞掉另行收录的字组。韩国字表中 `靑/青`、`鷄/雞`、`𮕩/衰` 等编码不同的韩式异体，按 Unicode IRG N2200 所列关系归入同一字组。
- **地区规范决定展示形。** 每列优先使用该地区的明确映射和字表主形；跨地区回退只允许明确归属于当前字组、没有被其他最终字组占用的形式。
- **单地区歧义保守拆分。** 若字组只在一个地区收录，而候选还属于另一字组，就保留传承参考形，并在两行之间建立双向“关系未确认”。`鎗/槍` 通过大陆候选 `枪` 互相提示，但不会因此合并。

五列确定后才选择行名。若中港台日已有证据，仍按原四地范围选择，以保持既有行名和网址；韩国独有条目才由五地结果决定。行名优先取字组自身名称，主条目和括注收录都足以保住名称；只有自身名称既未收录也未展示时，才使用不会占用其他字组 key 的安全回退形。因此独立的 `拐` 行保持 `拐 / 拐 / 拐 / 拐 / 拐`，另一个字组以 `柺` 为名，显示 `拐 / 枴 / 枴 / 柺 / 柺`。

## 公共数据语义

| 字段           | 含义                                                                                |
| -------------- | ----------------------------------------------------------------------------------- |
| `chars`        | 五地展示形；未收录时仍保留可绘制的参考字形                                          |
| `listing`      | 每格在该地区字表中的身份：`primary`、`glossed` 或 `unlisted`                        |
| `alternatives` | 该地区已收录、未展示且明确属于当前字组的形式；可搜索、作网址别名并显示字典引用      |
| `aka`          | 同一字组的其他名称，不表示地区候选                                                  |
| `uncertain`    | 双向未确认关系，记录相关行、触发字形和地区；只用于详情页“另见”                      |
| `old`          | 仅由 `JPShinjitaiCharacters` 的明确关系产生的日本旧字体，不由行名与日本列的差异反推 |

`listing` 的三个状态直接来自原始字表：

- `primary`：该形是主条目，详情页显示对应等级；
- `glossed`：该形只在主条目后括注，显示等级与“括注异体”；
- `unlisted`：适用字表均未收录，显示“未收录 · 显示参考字形”。

列表页不为这些状态增加角标。`tier` 和 `common` 继续用于现有筛选、排序与兼容；未确认关系不进入搜索、网址别名、字典引用或字体形式集合。

## 字形与笔画

字形比较使用 Source Han Sans 与 Source Han Serif 的地区 CMap。同一套字体内 CID 相同即视为同形；黑体或宋体任一方认为两地同形，最终就按同形处理。这样会过滤只由一套字体作出的设计区分，但也意味着本应用衡量的是 Source Han 的地区设计，而不是规范文件本身。

字表筛选、排序与详情页共用同一套地区笔画数，优先级为笔顺数据的轮廓数 → `kAlternateTotalStrokes` → 日本列的 `kRSAdobe_Japan1_6` → `kTotalStrokes`。香港复用笔顺的同形回退，按台湾、大陆、日本、韩国的顺序取首个可用数据。例如 `以` 五列为 `4 / 5 / 5 / 5 / 5`。

## 构建保证

数据和字体构建会强制检查：

- row key 与五列组合分别唯一；
- 每格 `listing` 与原始主条目、括注和未收录状态一致；
- `alternatives` 不属于其他最终字组；
- 五份建行主表的每个主条目都被展示或记录为候选，否则构建失败；
- 所有展示形和日本旧字体都能由生成的字体子集绘制。

## 已知限制

- 字形比较只覆盖通用黑体与宋体中的印刷字形，不代表手写习惯或教科书体。日语教科书体没有与中、港、台、韩共享同一字形池的正式地区版本；混用来源不同的字体会让地区差异与字体设计差异无法分开。
- Source Han 是高质量代理，但两套字体并非完全独立证据；真实地区规范差异仍可能被漏报。
- Source Han 的香港地区字形覆盖不完整，“只有香港不同”的模式可能少报。
- 笔顺数据不覆盖全部地区字形；回退用的 Unihan 地区笔画资料也覆盖有限，`kRSAdobe_Japan1_6` 仍是 provisional；缺少细分时港台会共用 zh-Hant 值。
- `unlisted` 格显示的是传承参考形，不表示该地区实际采用或规范收录该形。
- “关系未确认”表示现有公开来源不足以裁决；除非增加新的地区证据，否则这些字组会继续保守拆分。
- 台湾次常用表的独有条目不参与建行，这是产品范围，而非待修缺陷。
